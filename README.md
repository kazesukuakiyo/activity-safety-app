# 課外活動安全管理システム (学外活動届) — ローカル検証版

要件定義書 v3.0「Microsoft Lists Forms を入口とする最小実装」を、
**Python (FastAPI) の Web アプリ**として実装したものです。

Microsoft 365 の構成要素は次のように置き換えています。

| 要件書の構成要素 | このアプリでの実装 |
|---|---|
| Microsoft Lists Forms (学生入力画面) | `/reports/new` の Web フォーム |
| 活動届リスト (正本データ) | SQLite の `activity_reports` テーブル |
| 団体台帳 | `organizations` テーブル + `/orgs` 画面 |
| 活動資料 (行程表など) | `data/activity_docs/` フォルダ |
| 参加者名簿保管先 (個人情報管理サイト) | `participants` / `members` テーブル (職員・管理職のみ閲覧可)。名簿はファイルではなく 4 列の表として保持 |
| Power Automate (発番・照合・不足検査・通知・振分け) | `app/services/intake.py` |
| メール通知 | ローカルでは DB に記録し `/notifications` 画面で確認 |
| Entra ID 認証 | **後で実装**。今は疑似ログイン (`AUTH_MODE=dev`) |

## 動かし方 (初回)

**Python 3.11 以上**が必要です。Mac に最初から入っている Python は古いので、先に新しいものを入れてください。

- Homebrew がある場合: `brew install python@3.12`
- 無い場合: https://www.python.org/downloads/macos/ のインストーラーを実行
- 確認: `python3.12 --version` で `Python 3.12.x` と出れば OK

```bash
cd activity-safety-app

# 1. 仮想環境を作って有効化 (プロジェクト専用の Python 環境)
python3.12 -m venv .venv
source .venv/bin/activate        # Windows は: .venv\Scripts\activate
# → プロンプトの先頭に (.venv) が付く。以降の python / pip はこの環境を指す

# 2. ライブラリを入れる
pip install -r requirements.txt

# 3. 初期データ (団体台帳のサンプル) を入れる
python seed.py

# 4. 起動
uvicorn app.main:app --reload
```

2 回目以降は、ターミナルを開いたら `source .venv/bin/activate` → `uvicorn app.main:app --reload` だけで起動します。

ブラウザで http://localhost:8000 を開くと、ログイン画面が出ます。

## 名簿の考え方 (要件書 3.2 / 3.3 / 14 章の「添付振分け」への回答)

名簿は **「学籍番号・氏名・所属・学年」の 4 列の表**としてアプリが保持します。ファイルをそのまま保管するのではなく、中身を読み取って表にするので、
4 列以外の情報 (病歴・障害情報・常用薬・保護者連絡先など) が入ったファイルは取り込めません。

**年度部員名簿 (年 1 回)** の提出方法:

1. 「年度部員名簿」画面で大学指定の Excel テンプレートをダウンロード
2. 「部員名簿」シートに 1 行 1 人で記入
3. アップロード → 読み取った内容のプレビューを確認 → 「この内容で保存」

団体の代表者・副代表者が自団体の分を提出できます。**職員は紙やメールで受領済みの名簿を、任意の団体に代理で取り込めます。**
補助手段として Excel からのコピー貼り付けも使えます。加入・退部があれば同じ手順で提出し直します (丸ごと置き換え)。

**活動参加者名簿 (活動ごと)** は活動届フォームで作ります:

- 年度部員名簿がチェックボックスで並ぶので、参加する人にチェックを入れる
- 名簿に載っていない人 (新入部員・他団体からの参加) は「追加の参加者」に学籍番号・氏名・所属・学年を記入
- 大人数のときは貼り付けも可

年度名簿があっても活動ごとの参加者名簿は省略できません (要件どおり)。行程表・大会要項はこれまでどおりファイル添付です。

**名簿の閲覧範囲**

| 利用者 | 見えるもの |
|---|---|
| 学生 (代表者・副代表者) | 自分が代表者・副代表者の団体の年度名簿だけ。他団体は URL を直接開いても 403 |
| 学生 (それ以外) | 名簿は見えない。活動届は自分が提出した分のみ |
| 顧問 | 担当団体の活動届は見えるが、参加者名簿・年度名簿は見えない |
| 指定職員・管理職 | 全団体の年度名簿と全活動届の参加者名簿。職員のみ登録・取込ができる |
| システム保守担当 | 名簿は見えない (団体台帳のみ) |

## 動作確認の流れ (受入要件 12 章に対応)

1. **田中**でログイン → 「事前確認対象 = いいえ」で提出 → 状況が「確認済」になり、通知画面に「受付完了」が出る
2. **田中**で「事前確認対象 = はい」→ 部員一覧にチェック + 行程表を添付して提出 → 「未確認」になり、職員と顧問に確認依頼が出る
3. **田中**で「はい」なのに行程表も名簿も無しで提出 → 自動で「差戻し」になり、不足内容の通知が出る
   → 提出完了画面の「修正して再提出する」から不足分を足して再提出 → 同じ申請番号のまま「未確認」に戻る (第 2 版)
4. **高橋**でログイン → ダッシュボードで「未確認」を開き、状況を「確認済」に変えて備考を入れる → 田中宛てに結果通知が 1 回だけ出る (同じ値で再保存しても増えない)
5. **佐藤**でログイン → 田中の活動届 URL (`/reports/1`) を開く → 403 で見られない
6. **山本 (顧問)** で `/reports/1` を開く → 届は見えるが参加者名簿の欄は「指定職員・管理職のみ」と表示され、名前は見えない
7. **鈴木 (登山部 副代表)** でログイン → 「年度部員名簿」→ 登山部 → Excel テンプレートを落として記入 → アップロード → プレビュー → 保存。5 列目に何か書いた行があるとエラーになる。テニス部の名簿 URL (`/rosters/1`) を開くと 403

## 画面の工夫

- 活動届フォームは 6 つのブロックに分かれ、「事前確認対象 = はい」のときだけ 5 番 (行程・書類・名簿) が現れます。
- 5 番には「提出前チェック」があり、行程の概要・行程表・名簿の 3 点が揃っているかを入力中に表示します。揃わないまま提出すると自動で差戻しになります。
- 名簿の貼り付け欄は、入力中に「n 名を読み取りました」や「3 行目: 列数が 5 です」と即時に表示します。
- 活動届の詳細には「提出 → 職員の確認 → 確認済 → 活動終了」の進捗と、学生向けの「いま何を待っているか」の案内が出ます。職員には「確認済にする」「差戻す」のボタンがあり、差戻すときは備考 (理由) が必須です。
- スマホでは一覧やダッシュボードの表がカード形式に切り替わります。

## 画面一覧

| 画面 | URL | 使う人 |
|---|---|---|
| 活動届フォーム | `/reports/new` | 学生 |
| 差戻し後の再提出 | `/reports/{id}/edit` | 提出した学生 (差戻し中のみ) |
| 活動届一覧・詳細 | `/reports`, `/reports/{id}` | 学生は自分の分のみ、顧問は担当団体のみ、職員・管理職は全件 |
| ダッシュボード | `/dashboard` | 職員・管理職。いま学外にいる団体、7 日以内の予定、未確認、差戻し中、場所・日付での検索 |
| 年度部員名簿 | `/rosters` | 代表者・副代表者は自団体を登録・更新、職員・管理職は全団体を閲覧 |
| 団体台帳 | `/orgs` | 職員・システム保守 |
| 通知 (送信箱) | `/notifications` | 全員 (自分宛てのみ。職員は全件) |

## Entra ID 認証に切り替えるとき

`app/auth/entra.py` のコメントに手順を書いています。概要:

1. `pip install msal`
2. Entra ID にアプリ登録 (リダイレクト URI: `http://localhost:8000/auth/callback`)
3. `.env` に `AUTH_MODE=entra` とテナント ID / クライアント ID / シークレットを設定
4. `entra.py` の `/auth/login` と `/auth/callback` を実装し、取得したメール・氏名を `login_user()` に渡す
5. 役割 (学生/職員など) は Entra ID のグループかアプリロール、またはアプリ側の職員メール一覧で決める

画面や業務処理は `app/auth/base.py` の `User` しか見ていないので、他は変更不要です。

## 要件書との対応で意図的に簡略化した点

- **メール送信**はしていません (通知画面に記録)。本番では `services/notify.py` を差し替えます。
- **DB は SQLite** (ファイル 1 つ)。本番で複数人が同時に使うなら PostgreSQL 等に変えます (`DATABASE_URL` を変えるだけ)。
- 学生が「自分が提出した活動届」を見られ、差戻し中なら修正・再提出できます (要件書では将来検討の範囲ですが、運用上ほぼ必須なので入れています)。他団体・他人の届は見えません。
- 添付ファイル (行程表など) の上限は 20MB です。
- 年度部員名簿の更新は「貼り付けた内容で丸ごと置き換え」です。1 人だけ直す UI は作っていません (Excel 側で直して貼り直す前提)。

## DB を作り直したいとき

テーブル構成を変えた版に更新したあとや、検証データを消したいときは、`data/` フォルダを削除して `python seed.py` をやり直してください。
